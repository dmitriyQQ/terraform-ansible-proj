# Terraform Proxmox LXC

Проект для управления LXC-контейнерами в Proxmox VE с помощью Terraform.

Основная цель проекта — создать масштабируемую и удобную структуру для развертывания контейнеров с поддержкой:

* нескольких контейнеров через единую переменную `containers`;
* нескольких сетевых интерфейсов;
* профилей ресурсов (`small`, `medium`, `large`);
* переопределения параметров профиля;
* валидации входных данных;
* модульной архитектуры Terraform.

## Возможности

* Создание нескольких LXC-контейнеров за один запуск Terraform.
* Использование готовых профилей ресурсов.
* Частичное переопределение параметров профиля.
* Поддержка нескольких сетевых интерфейсов.
* Централизованное хранение платформенных настроек.
* Проверка корректности входных параметров до выполнения `terraform apply`.

## Профили контейнеров

Для упрощения создания контейнеров проект поддерживает готовые профили ресурсов.

Доступны следующие профили:

| Профиль | RAM     | SWAP    | CPU | Disk |
| ------- | ------- | ------- | --- | ---- |
| small   | 1024 MB | 512 MB  | 1   | 2G   |
| medium  | 2048 MB | 1024 MB | 2   | 4G   |
| large   | 4096 MB | 2048 MB | 4   | 8G   |

Профиль указывается через параметр `profile`:

```hcl
containers = {
  web = {
    hostname = "web-01"

    profile = "small"

    network = {
      eth0 = {
        ip = "192.168.0.10/24"
      }
    }
  }
}
```

В этом случае контейнер получит все параметры из выбранного профиля.

### Переопределение параметров профиля

При необходимости отдельные параметры можно переопределить.

Например, контейнер может использовать профиль `large`, но иметь только одно ядро процессора:

```hcl
containers = {
  app = {
    hostname = "app-01"

    profile = "large"

    resources = {
      cores = 1
    }

    network = {
      eth0 = {
        ip = "192.168.0.20/24"
      }
    }
  }
}
```

В результате будут использованы:

* memory = 4096
* swap = 2048
* cores = 1

Параметры профиля применяются первыми, после чего пользовательские значения переопределяют их через механизм `merge()`.

## Примеры конфигурации

### Минимальная конфигурация

Контейнер будет создан с параметрами по умолчанию, определёнными в проекте.

```hcl
containers = {
  test = {
    hostname = "test-01"

    network = {
      eth0 = {
        ip = "192.168.0.100/24"
      }
    }
  }
}
```

### Контейнер с профилем

Использование готового профиля ресурсов.

```hcl
containers = {
  web = {
    hostname = "web-01"

    profile = "small"

    network = {
      eth0 = {
        ip = "192.168.0.101/24"
      }
    }
  }
}
```

### Профиль с переопределением параметров

Профиль применяется первым, после чего пользовательские значения переопределяют необходимые параметры.

```hcl
containers = {
  app = {
    hostname = "app-01"

    profile = "large"

    resources = {
      cores = 1
    }

    network = {
      eth0 = {
        ip = "192.168.0.102/24"
      }
    }
  }
}
```

### Полностью ручная настройка

Контейнер создаётся без использования профилей.

```hcl
containers = {
  db = {
    hostname = "db-01"

    resources = {
      memory = 8192
      swap   = 2048
      cores  = 4
    }

    storage = {
      root = {
        size = "20G"
      }
    }

    network = {
      eth0 = {
        ip      = "192.168.0.103/24"
        bridge  = "vmbr0"
        gateway = "192.168.0.1"
      }
    }
  }
}
```

### Несколько сетевых интерфейсов

Проект поддерживает создание нескольких сетевых интерфейсов через динамический блок Terraform.

```hcl
containers = {
  monitoring = {
    hostname = "mon-01"

    profile = "medium"

    network = {
      eth0 = {
        ip = "192.168.0.110/24"
      }

      eth1 = {
        ip = "10.10.10.10/24"
      }
    }
  }
}
```

## Основные переменные

### Параметры подключения к Proxmox

| Переменная           | Описание                                   |
| -------------------- | ------------------------------------------ |
| `proxmox_api_url`    | URL Proxmox API                            |
| `proxmox_api_id`     | ID API-токена                              |
| `proxmox_api_secret` | Секрет API-токена                          |
| `lxc_passwd`         | Пароль пользователя root внутри контейнера |

### Параметры платформы

| Переменная    | Описание                                | Значение по умолчанию                                      |
| ------------- | --------------------------------------- | ---------------------------------------------------------- |
| `target_node` | Узел Proxmox для размещения контейнеров | `hostname`                                                 |
| `ostemplate`  | Шаблон операционной системы             | `local:vztmpl/ubuntu-22.04-standard_22.04-1_amd64.tar.zst` |
| `storage`     | Хранилище Proxmox для rootfs            | `local-lvm`                                                |

### Параметр containers

Все контейнеры описываются в единой переменной `containers`.

Структура контейнера:

```hcl id="06m9nl"
containers = {
  container_name = {
    hostname = string

    profile = optional(string)

    network = {
      interface_name = {
        ip      = string
        bridge  = optional(string)
        gateway = optional(string)
      }
    }

    resources = optional({
      memory = optional(number)
      swap   = optional(number)
      cores  = optional(number)
    })

    storage = optional({
      root = {
        size = string
      }
    })
  }
}
```

## Валидация

Проект выполняет проверку входных данных до создания ресурсов.

Проверяются следующие условия:

* количество CPU должно быть больше 0;
* объём памяти должен быть не менее 512 MB;
* профиль должен иметь одно из значений: `small`, `medium`, `large`;
* размер диска должен быть указан в формате `<число>G`.

Примеры корректных значений:

```text id="8dwdmf"
2G
4G
8G
16G
100G
```

Примеры некорректных значений:

```text id="42kddq"
0G
01G
5M
10GB
disk
```

## Безопасность

Не рекомендуется хранить реальные токены и пароли в репозитории.

Файл `terraform.tfvars` следует добавить в `.gitignore`.

Для публикации проекта рекомендуется использовать файл:

```text id="f3z0kt"
terraform.tfvars.example
```

с тестовыми значениями вместо реальных секретов.
